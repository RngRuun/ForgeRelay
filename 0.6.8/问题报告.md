# ForgeRelay 0.6.7 问题报告（由 0.6.8 修复）

报告日期：2026-10-29。仅记录应用行为和故障，不含应用源码、核心框架、凭据、用户附件或私有会谈。

## 已确认问题

1. 长工具输出在聊天记录中被直接裁切，JSON 可停在字段中间，界面没有说明预览限制。后台日志也存在独立预览限制。用户继续滚动不能恢复被裁切的部分。
2. 普通会谈未延续同一角色的原生 Codex 会话。工具读取历史不能直接延续，重复拼装输入也使缓存复用不稳定。缓存命中率与任务成功率应分开评估。
3. 会谈快照只取最近一段消息和工具摘要。完整记录在磁盘保存不代表每次请求都拥有全部原文。
4. Windows 短暂占用状态文件时，重命名操作可能报 EPERM。保存异常可能向工具调用传播，造成“工具已完成但显示失败”。
5. 空文件写入范围的调查合同禁止任意命令，但合同可能同时要求真实数值验证；缺少专用计算路径时不能完成验收。禁止子代理的合同也没有得到一致的能力过滤。
6. 工具桥原有固定 240 秒等待时间与外层长任务期限不一致。连接结束后的执行生命周期也需要统一清理。
7. 续接会话用量基线缺失或重置时，成功回答不能仅因无法精确计量而被判失败。

## 影响与边界

这些问题能导致重复读取、无效重试、输出展示不完整或工具失败，但不意味着每次模型请求都被截断，亦不意味着所有失败都是 API 传输错误。新建会话仍可能命中服务端缓存。

旧版已被裁切且没有另存全文的日志无法凭空恢复。模型真实上下文窗口、服务端缓存保留与网络可用性仍由实际模型和服务决定，不能承诺无限容量、99% 命中或零失败。
