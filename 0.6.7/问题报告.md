# 0.6.7 修复前的问题报告

日期：2026-10-29。受影响版本：0.7.6；本次按用户指定版本号发布为 0.6.7。

## 已核实问题

1. 会谈虽然可以设置不限轮数、调用数和 Token 预算，内部仍独立限制每次发言 8 轮工具回路、工作台 10 轮、同一派工 4 次及单次派工总时长。复杂调查会在仍有实际进展时被中断。
2. 会谈和派工历史超过固定字符阈值后重建检查点。当前状态仍在，但已经取得的完整工具结果可能退出可见历史，模型需要重新读取，甚至把截断的日志误认为原文缺失。
3. 用户样本的四次派工分别是：工具回路耗尽、最终交付 JSON 非法控制字符、提交后因内容问题被退回、再次工具回路耗尽。不能将四次都归因为模型无法完成。
4. 模型提出“增加原合同额度”的人工选项，但后台没有对应的额度调整能力。人工介入同时推进方向版本，旧合同被标记过时，进一步阻止原合同续办。
5. 工具日志是摘要；以摘要替代重新读取完整证据，会造成研究对象、文献或证据 ID 对应错误。正确的独立验收退回不应被绕过。

## 范围

这属于执行连续性、上下文管理和恢复入口的实现缺口。本文不证明研究框架本身正确或错误，不包含核心源码、原始会谈、个人文件或密钥。

修复及验收见 [0.6.7 解决方案](https://github.com/RngRuun/ForgeRelay/blob/bug-resolve/0.6.7/解决方案.md)。
