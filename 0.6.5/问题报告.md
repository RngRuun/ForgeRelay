# ForgeRelay 0.6.5 问题核验与 0.7.6 修复报告

日期：2026-10-28。提交位置：`bug-report/0.6.5/`。本报告不包含应用源码、内部框架公式、用户原始会谈、附件或密钥。

## 核验结论

用户反馈的缓存效率和界面问题属实。实际会谈还存在会增加重复调用的恢复问题。问题主要在应用的上下文传输、执行续接和结果校验层；这份样本不能证明某个模型的推理能力失效，也不能证明研究方案本身不成立。

### 1. 缓存效率在角色冷启动及执行重试时下降

- 新角色需要建立自己的完整上下文，首次请求与连续请求的命中情况差异很大。总体比例不能等同于后续连续请求的比例。
- 原执行重试路径重新发送任务上下文，未完整延续同一任务已经产生的真实交互历史。
- 相同资料被反复读取和传输，增加输入开销。
- 修复：改进执行续接、配置变更影响范围和相同资料的传输复用。模型配置、原文可获得性、真实取证与独立审查约束保持有效。
- 缓存比例只采用服务商返回的实际用量。服务商缓存属于尽力提供，不能保证所有角色、所有首轮请求达到 99%，也不通过填充输入提高比例。

### 2. 有实质内容的审查被格式与提问规则中断

- 已标记为非阻塞的补充问题仍可能触发人工提问校验失败。
- 对异议的完整回应仅出现在回应字段中时，可能因缺少单独的分析登记被整条拒绝。
- 修复：明确生成要求，并在不改变观点、事实、表决与关闭权限的情况下保留已有内容、恢复合法业务结构。真正的阻塞缺口仍按原规则处理。
- 已使用原样本中两条被拒绝的内容完成离线业务校验回放。两条均能保留原发言、回应和异议通过校验。此项是校验回放，不代表重新推理或重新建立当时的网络会话。

### 3. 人类介入记录显示内部动作标识，造成文字重叠

- `DISCUSSION_CHOICE` 等内部动作名称被直接显示为宽标签，与右侧标题重叠。
- 修复：使用固定尺寸图标、中文动作名称和可换行内容；未知动作也不会泄露原始内部名称。
- 同时修正旧会谈在窄窗口下的操作菜单文字挤压。

### 4. 0.6.5 Release 自动源码包与功能源码的定位存在歧义

- 核验时，`v0.6.5` 标签指向 `17595be85fc90bd4909f4d3db6ce8f325f77442b`，该提交的应用版本仍为 0.6.1，未发现说明中所述联网功能实现。
- GitHub 自动生成的 Source code 压缩包是该标签对应的仓库快照，不会从已编译的程序中反向生成源码。
- 初次核验时 `contribution` 分支说明功能源码尚未推送；随后用户另行提供 `ForgeRelay-v0.6.5-source.zip`，其中确实包含联网实现与测试。该独立源码包与 Release 自动生成的标签快照不同。
- 已以独立源码包为准整合协作者的联网工具接口、权限开关、实际执行路径与测试；保留后续修复，并加强重定向拒绝和完整正文处理。未改动既有公共源码历史和旧标签。
