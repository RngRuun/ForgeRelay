## 1. 核验结论

报告的主要问题成立。需要区分程序缺陷、符合设计但缺少说明的行为，以及依赖外部环境的性能数字。

| 编号 | 判定 | 本地处理结果 |
| --- | --- | --- |
| F-1 | 属实：`room` 被当成隐式任务过滤条件 | 默认展示全部任务；只有主动选择“只看本会谈”才过滤。任务列表、任务中心、记忆、成果和回收站统一采用显式范围。 |
| F-2 | 属实：当前任务统计被误读为全局状态 | 三个主页面常驻后台任务入口，约每 2 秒读取全局轻量导航数据；点击直接定位实际任务。无调用文案明确限定“当前任务”，计量文案限定“当前视图”。 |

## 2. 前端与交互修复

### 2.1 任务范围与跨页面导航

工作台页面 URL 中的 `room` 现在表示来源会谈和任务关联上下文，不会默认让未关联任务或其他会谈的任务消失。只有 `scope=room` 或用户点击范围按钮时，工作台才进入本会谈范围。API 为兼容旧调用，单独传 `room` 或 `task` 仍按相应范围筛选；需要全量时使用无参数请求或显式 `scope=all`。页面路由与 API 筛选各自有明确语义。

- 左侧任务行区分“本会谈 / 其他会谈 / 未关联会谈”。
- 任务控制、任务中心、共享记忆与成果页显示范围、可见数量及全部数量；回收站沿用当前显式范围。
- 导航接口携带 `roomId`、开始时间和恢复信息，避免切页后靠旧的本地选择猜测目标任务。
- 后台入口独立于页面过滤；即使当前只看 B 会谈，也能看到其他会谈中运行的 C 任务并一键进入。
- 任务选择同步 URL；三个主要入口“三方会谈 / 任务控制 / 模型实验室”继续常驻侧边栏。
- 全局轻量轮询不调用模型；请求有超时，避免单次挂起永久阻塞后续状态刷新。

范围 API 示例：

```text
GET /api/tasks
GET /api/tasks?scope=room&room=<roomId>
GET /api/tasks?scope=task&task=<taskId>
GET /api/tasks?scope=room&room=<roomId>&deleted=true
GET /api/navigation
```

响应中 `scope` 描述当前范围，`counts.visible` 描述当前列表，`counts.total`、`running`、`queued`、`active` 等提供全局对照。缺少必要 ID 或范围无效会返回错误。

### 2.2 等待、重试和参与者

调用开始即产生记录，尚无答案时展示等待状态；界面按真实开始时间更新耗时，CLI 心跳携带重连次数和静默时间。心跳只更新调用状态，不把内部 JSON 倾倒进聊天，不制造虚假进度百分比。

默认最长调用时间仍为 900 秒，可设置为 30–3600 秒。Codex 无新事件超时可设置为 0–3600 秒，默认 0，即关闭。没有采纳“90 秒无输出一律杀掉”的默认值，因为长时间推理或工具执行也可能合法静默。

普通聊天继续由 Lead 回应；团队互审仅按用户选择或已有讨论许可进行。界面说明 DeepSeek/Codex 此轮是否实际参与，不能以另一模型的回复冒充。用户设置的角色、Lead、叛逆值和轮数保持有效。

### 2.3 额外发现：连续切页后删除请求卡住

浏览器完整路径回归发现：单独打开任务页可以删除，但在任务控制、实验室、会谈、图表之间连续切换后，删除按钮会进入等待而请求不完成。原页面没有显式释放 SSE；浏览器保留文档时，旧实时连接可能继续占用同源连接池。

已新增统一实时连接生命周期：

1. `pagehide` 关闭当前事件连接。
2. 浏览器恢复页面时重新连接，并接收服务端初始快照。
3. 忽略已关闭连接晚到的消息。
4. 主动销毁连接时移除生命周期监听器，不再自行复活。
5. 会谈离页时停止旧轮询，返回后恢复，不影响草稿保存。

补齐后，同一条连续导航路径中的删除与恢复通过，两次完整浏览器回归均通过。删除仍是可恢复的移入回收站；运行中的任务仍需先停止，避免遗留继续执行的隐藏任务。

### 2.4 视觉与可用性检查

沿用原有 taste-skill Data terminal 方向，保留用户明确要求的磨砂玻璃、悬停反光、柔光和活动卡片效果。本次主要改善信息层级和状态可信度，没有另造一套不一致的按钮体系。

检查了任务控制、模型接入、三方会谈、模型实验室四个页面，在 1440、768、390 像素宽度下的首屏与整页截图。补大新增后台入口和参与者说明文字；窄屏菜单用有可访问名称的省略号按钮，移除 `font-size:0` 隐藏文字的实现。

最终检查为四页均 **0 FAIL**。检查器对 `gradient`、`button-fx`、`heavy-shadow` 使用了有记录的例外，原因是这些正是用户明确要求保留的视觉效果；没有关闭布局或溢出检查。仍有部分既有小字、头像承载、边框和字体告警，属于后续视觉精修项，不能把通过自动测量等同于达到设计奖项标准。没有页面横向溢出。

## 3. 后端、协议与状态修复

### 3.1 Codex 事件与完成判定

原实现把首次临时 `type:error` 留在致命错误变量中，之后即使收到答案、`turn.completed` 并退出 0，仍拒绝结果。

现在临时连接错误和传输回退分别进入重试/警告记录。只有退出码为 0、有有效输出并收到完成事件，且无终止失败时才算成功。`turn.failed`、非零退出、缺少完成事件、用户取消和超时仍失败或中断，不能通过“忽略所有错误”制造成功。

失败对象和调用记录保留已经收到的文本、重连次数及已有用量。没有返回用量时标记未知，不写成 0。测试回放覆盖报告中的重试、WebSocket 回退、最后成功序列，也覆盖真正失败、非零退出及不完整输出。

官方参考：[Codex 非交互执行文档](https://developers.openai.com/codex/noninteractive)。

### 3.2 DeepSeek 协议恢复

恢复仅用于满足结构要求、已确认当前规则、人工版本和方案版本的审查/综合输出：

- `signals.objectionIds` 中不存在的 ID 被移除，但该 signal 的正文、证据、影响、`blocking`、`humanOnly` 和选项保留，并生成可审计警告。
- 新异议 ID 按实际登记顺序及同角色同标题去重规则计算，不通过猜测“最近一个异议”来替换。
- 对其他角色异议的关闭请求，保留为回应/复核建议；原异议保持原状态，仍由提出者决定是否关闭。重复关闭已关闭异议也不会再执行关闭。
- 不存在的关闭目标、理由不足、过时哈希、过时人工约束、错误投票、缺失工具证据仍严格拒绝。
- 独立表决阶段不自动修补投票；不读取另一角色的私有投票来代替独立判断。

其他校验错误不再自动发起三轮完整业务重试。完整无效输出及准确原因保存在调用记录中，会谈进入待处理；用户修正或选择继续后才能产生下一次调用。不会把不可靠的内容悄悄变成共识，也不会用小模型替代原模型进行实质性改写。

### 3.3 中断恢复与兼容性

引擎重启后，对原运行、队列、暂停、等待人工的任务记录恢复元数据；悬空运行调用改为中断并补结束时间。既有文件、已完成调用和已知用量保留，未知用量明确标记。恢复提示可确认，用户可以复制任务后继续，模型调用不会自动重启。

另外修复了本地开发基线中的三个回归：两个旧缓存诊断夹具未包含异议数组时的兼容问题，以及 CLI 不接受当前 `humanLoopVersion=2` 后台的问题。CLI 仍拒绝未知协议版本和无关服务。

## 4. 代理、密钥与诊断

### 4.1 一套代理策略覆盖两个模型

支持系统/环境代理、自定义 HTTP(S) 代理、直连三种模式。桌面通过 Electron 获取系统代理；独立 CLI 后台在 Windows 读取系统代理配置。显式环境变量优先，并保留 HTTP、HTTPS 分别配置。按 PAC 返回顺序处理代理或直连，不把 `DIRECT` 优先的结果强行转为代理。

Codex 子进程显式继承规范化代理环境；DeepSeek 的模型列表、聊天及工作执行请求采用同一策略。`localhost`、`127.0.0.1`、IPv6 回环地址绕过代理，避免影响本地工具桥。自定义地址拒绝用户名密码、路径和换行，公开状态仅显示代理主机。

HTTP 传输新增锁定的 `undici@8.12.3`，同时使用同版本的 fetch 与 dispatcher，避免与 Node 内置 fetch 的不同 dispatcher 协议混用。源码最低 Node 版本为 22.19.0；桌面内置 22.23.4 满足要求。构建清单包含所需模块和策略文件，工作流补上根目录 `npm ci`。

这里实现的是 HTTP(S) 代理，不声称已支持所有 SOCKS、公司认证代理或任意 PAC 环境；这些环境仍需选择兼容的本地 HTTP 代理入口。官方参考：[Electron resolveProxy](https://www.electronjs.org/docs/latest/api/session#sesresolveproxyurl)、[Undici EnvHttpProxyAgent](https://github.com/nodejs/undici/blob/main/docs/docs/api/EnvHttpProxyAgent.md)。

### 4.2 验证连接与真实推理分开

“验证连接”只检查 CLI 登录、DeepSeek 模型目录和网络端点，不产生模型推理。收到端点的 HTTP 响应只能说明网络可达，不能等同于模型权限或推理验证通过。

“真实推理测试”需要用户单独点击选择 Codex 或 DeepSeek，按钮附近明确标注会产生用量；接口要求 `confirmPaid=true`。一次最小请求，最长 120 秒；记录实际状态、请求标识和返回用量。它不建立假任务、不冒充团队讨论，活动任务/讨论/诊断期间互斥；接入配置保存也有并发保护。

诊断记录独立保存在本机 `connection-checks.json`，不会伪装成业务会谈的 token。此次没有用真实 Codex 推理来宣称当前账号的权限已经验证成功。

### 4.3 主动选择的本机加密保存

默认不保存密钥。只有用户勾选“在这台电脑上加密记住密钥”并保存时，由桌面主进程通过私有 IPC 调用 Electron 异步 safeStorage，加密文件为本机 `deepseek-key.encrypted`。新引擎启动时恢复；普通浏览器/独立后台不提供不可兑现的加密保存选项。

加密不可用时拒绝保存，不退回明文；无法解密时保留原文件并显示原因。清除操作同时清理当前密钥和本机加密副本，不影响其他文件。用户环境变量注入的密钥，下一次启动仍由该环境控制。

Windows 用户级加密不能防止同一 Windows 用户下的其他程序读取。密钥不进入模型配置、聊天、任务数据、浏览器存储、Markdown 或 GitHub。官方参考：[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage/)。

## 5. 成本与缓存：具体优化及边界

没有改变模型、思考开关、推理强度、最大输出长度、用户互审轮数或预算，也没有为了费用删除人的约束、异议、证据或工具历史。

1. 保留 Lead 自然聊天和按需讨论：没有讨论许可时不自动启动群体互审。现有自适应入口已经把规则确认放入首次实质发言，不为普通聊天单独执行空 ground。历史非自适应会谈保留原流程兼容，不能把它们的旧调用当成新流程消耗。
2. Codex 仍使用原生结构化输出 schema，只删除提示词里相同 schema 的文字副本。讨论、聊天、灵活调度分支分别减少 2,043、269、1,239 个重复字符。DeepSeek 仍收到必要 schema。这里统计的是字符，不能冒充真实供应商 token 节省比例。
3. 同一任务状态改为紧凑 JSON 序列化。固定五步骤夹具由 1,163 字符变成 732 字符，减少 431 字符；解析后数据完全相同。这不是丢字段或摘要压缩。
4. 首次调度明确要求先制定依赖计划与验收标准，避免在无计划时猜测执行/复查动作；引擎的实际验收约束仍保留。
5. 可安全恢复的语义引用问题不重新调用；其他协议失败不再自动重复三次完整推理。
6. 保留稳定 system 前缀、确定性工具排序、只追加上下文、完整工具响应及增量快照。网络/密钥设置不再无意义地保存同一份模型配置，减少无关配置版本变化。

无状态请求仍需发送必要规则；不能因为上一请求发过 system，就在下一次删除规则。缓存依赖供应商实际复用，界面继续展示官方命中 token 与调用状态，不用填充无意义前缀来提高百分比。

报告中的 154,980 tokens 是其特定讨论样本，29 万的完整历史未在本次重新付费跑一遍。不能把上述字符变化换算成未经实测的成本下降，也不能保证 Codex CLI 自带的工具/运行环境输入低于某个固定 token 数。用户选择的多角色、多轮互审本身会产生真实成本，本次没有通过缩减这些要求来满足数字目标。
