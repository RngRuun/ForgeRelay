## 2. 本轮补修的七类问题

### R-1：DeepSeek 超时设置未贯通

接入页已有单次调用等待设置，但聊天/讨论与执行适配器仍写死 `180000ms`。新测试设置 47 秒，修复前实际构造出的两个超时均为 180 秒，确认不一致。

现在两条路径优先使用接入配置的调用超时；未提供网络配置的独立适配器仍兼容其原有默认值。测试确认两次请求均使用 47 秒，且 `max_tokens` 等模型参数没有被降低。

### R-2：失败或拒绝后，已完成的工具历史没有完整进入后续上下文

原逻辑只在整次回复通过业务校验后保存 provider exchange。因此，某轮工具已经完成，但下一次 HTTP 返回失败，或最终聊天 JSON 缺少必填字段时，工具证据可能没有保留在私有续接历史中。聊天调用还缺少明确的 `validationError` 与原始拒绝输出。

现在每个完整工具回路完成后就保存真实消息边界，最终回复不合规也保留原文；续接操作检查冻结前缀并去重，不允许改写已保存历史。聊天格式错误写入明确的校验错误与完整拒绝输出，不当成有效答案发布。

新增场景覆盖：

- 工具已返回证据，最终 JSON 不合规：保留工具请求、结果和原始回复，不产生有效用户答案。
- 第一轮工具已完成，第二次 HTTP 返回 503：保留第一轮完整证据，第二次调用如实失败，没有自动重复付费请求。
- 旧缓存边界、完整工具历史、角色独立性和独立表决测试继续通过；独立投票仍不复用其他角色或旧票历史。

### R-3：旧探测结果覆盖新配置，以及非法模型 ID 的部分保存

发现两个接入状态边界：修改代理后旧网络状态可能仍显示已验证；更换或清除密钥时，旧的在途探测可能随后返回并把状态改回成功。此外，非法模型 ID 原先可能被忽略，其他配置却先保存，接口仍返回成功。

现在接入配置变更会推进检查版本并清空旧验证状态；探测只允许回写同一版本，过期结果标记 `stale`，不能恢复旧成功状态。模型 ID 在修改密钥、代理或调用桌面保存前校验。

通过隔离的实际 server 复现并验证：让旧密钥检查延迟返回，在此期间清除密钥并修改代理；旧结果返回后，状态仍为未配置/未验证，新代理保持生效。非法模型 ID 返回 400，密钥与代理不被该请求部分修改。

### R-4：筛选后 URL 与所选任务不一致

从全局 C 任务切换为“只看本会谈”后，列表和选择会改为 B，但 URL 可能仍保存 C。

已改为先确定筛选内的实际选择，再更新 `scope` 和 `task` 参数。浏览器验证选择、URL 和刷新后的定位一致。

### R-5：后台状态断线后仍显示旧的运行信息

旧状态轮询失败时保持了上次数据，却没有说明已经过期。

现在保留上次任务记录以供定位，同时明确显示“状态待更新”，可访问名称和提示说明数据暂不可达。服务恢复后自动恢复正常状态，不把断线误报成“无任务”，也不把旧记录当成实时确认。

### R-6：桌面启动/退出竞态

实际原生桌面连续启动、保存密钥和快速退出时，复现过 `Object has been destroyed`，退出码为 1。异步引擎连接、页面加载或状态发送可能晚于窗口销毁。

已对窗口和 WebContents 做存活检查；退出阶段取消后续加载；处理正常的导航取消；IPC 回应遇到断开时不产生未处理错误。没有在普通运行时屏蔽所有异常。

修复后，最终代码完成五组原生集成检查，每组三次启动与退出，共 **15 次**，均正常退出；同时验证密钥恢复和清除，不只是测试加密函数替身。

### R-7：退出接口响应尚未交付便结束进程

本地 Windows 构建的包内引擎测试复现过 `/api/shutdown` 的 `ECONNRESET`。原逻辑写出 JSON 后立即退出，未完整处理请求体与连接收尾。

现先消费请求体，在响应完成后进入关闭流程，等待服务器连接收尾；对无法结束的连接保留有界关闭机制。实际 HTTP 测试验证收到 200 和 `{stopping:true}`，之后进程正常退出；更新后的包内引擎也通过启动、资源与关闭检查。
